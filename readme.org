#+TITLE: ChatGPT Userscript

* What this is
=basic.js= is a userscript for =https://chatgpt.com/*= that helps with:
- repeated message sending with delay
- bulk downloading generated images

* Install
1. Install a userscript manager (Tampermonkey/Violentmonkey).
2. Create a new script and paste =basic.js=.
3. Open =https://chatgpt.com/=.

* Quick use (browser console)
The script exposes helpers on =window=:
- =sendMessage(msg, checkInterval, sleep, timeout)=
- =sendMessageRepeatedly(msg, n, sleep, mode, pick_output_dir)=
- =sendMessageRepeatedlyArray(msgs, sleep, sep, prefix, postfix, selection, mode, pick_output_dir)=
- =sendMessageRepeatedlyArrayChooseFile(sleep, sep, prefix, postfix, selection, mode, pick_output_dir)=
- =openNewChat()=
- =skipCurrentPrompt()=
- =clickDallEDownloadButtons(pick_output_dir)=
- =waitForImageGenerationLimitReset(previousAssistantTurnCount=0)=
- =MAGIC_RETRY=

Examples:
#+begin_src js
sendMessage("Hello");
sendMessageRepeatedly("Thanks, continue.", n=2, sleep=60,);
sendMessageRepeatedlyArrayChooseFile(sleep=10, sep="\n", prefix="", postfix="", selection="", mode="new_chat_image");
sendMessageRepeatedlyArrayChooseFile(sleep=10, sep="\n", prefix="", postfix="", selection="4..10, 12, 20..", mode="new_chat_image", pick_output_dir=true);
sendMessageRepeatedlyArrayChooseFile(sleep=10, sep="\n", prefix="", postfix="", selection=[4, 5, 6, 12, -1], mode="new_chat_image", { imageRetryPrompts: [MAGIC_RETRY, { prompt: "First rewrite the prompt and put it in a markdown code block.", image_expected_p: false }, "Generate using the new safe prompt!"] });
skipCurrentPrompt();
clickDallEDownloadButtons();
waitForImageGenerationLimitReset();
#+end_src

* Notes
- =sleep= in =sendMessageRepeatedly= is in seconds.
- =timeout= in =sendMessage= is in seconds.
- =mode= defaults to =continuous=.
- =mode="new_chat_image"= always opens a fresh chat before the first prompt, then waits for a visible generated image; if the latest assistant reply is a recognizable refusal and the composer is ready again, it immediately runs the next retry step instead of waiting out the full image timeout. Otherwise, on each timeout it runs the next retry step (by default: =MAGIC_RETRY=, then the creative-license guidance, then =Generate!=). If the retry queue is exhausted, the image timeout bubbles out as before; only UI/page-level recovery loops keep retrying automatically.
- Once a generated image is visible, the downloader retries that same image forever with backoff (=1s → 2s → 4s ... capped at 60s=) and a per-attempt fetch timeout of 45 seconds; it re-resolves the current tile/asset URL on every retry instead of regenerating a new image.
- =skipCurrentPrompt()= works during active array runs only (=sendMessageRepeatedlyArray(...)= / =sendMessageRepeatedlyArrayChooseFile(...)=). It cooperatively skips the current prompt at the next safe checkpoint and advances to the next selected prompt.
- If =skipCurrentPrompt()= is used while a generated image is stuck in download-retry, the script saves a small diagnostic text file (prompt, prompt index, image index, asset URL, last error, retry count) before advancing.
- =MAGIC_RETRY= means: open a new chat and resend the original image prompt.
- In =new_chat_image= mode, if ChatGPT replies with an image-limit reset message like =You can create more images when the limit resets in ...=, the script treats that as a special case, waits through the reset window, then retries by opening a new chat and resending the original prompt instead of consuming the fallback retry queue.
- The refusal fast-retry behavior is controlled by top-level constant =ENABLE_IMAGE_REFUSAL_FAST_RETRY= (default: =true=).
- =openNewChat()= no longer just fires the shortcut and returns. It now waits until a fresh-chat surface is actually ready, resolving visible dialogs with a conservative allowlist (=Leave= / =Discard= / =Stay= / =Cancel= / =Close= etc.), trying a visible =New chat= control when present, and falling back to the shortcut.
- If the composer/send button gets stuck during retries, the script now enters an in-page recovery loop instead of throwing a fatal =Operation timed out.= It keeps re-finding the composer, dismissing safe dialogs, and logging heartbeat diagnostics until the prompt becomes sendable or you call =skipCurrentPrompt()=.
- When send/composer readiness returns, the console now logs a =[ready-debug]= event with the latest detected assistant message and whether it matched =IMAGE_REFUSAL_TEXT_PATTERNS=.
- In array helpers, progress/failure logs show both selection progress and the absolute prompt index (0-based), e.g. =selection 2/5, prompt 12=.
- =selection= accepts =""= / omitted for all prompts, comma-separated DSL strings like =2..=, =..5=, =4..10, 12, 20..=, and literal JS arrays like =[4, 5, 6, 12, -1]=.
- Range ends in the DSL are inclusive: =4..10= means prompts =4= through =10=.
- Negative indices are allowed in both DSL strings and JS arrays, e.g. =-1= means the last prompt and =-3..-1= means the last three prompts.
- Selection order and duplicates are preserved exactly as written.
- =sendMessageRepeatedlyArrayChooseFile(...)= skips prompts that are only whitespace after splitting by =sep=, and applies =selection= to that filtered prompt list.
- Old =from=/=to= array-helper calls now fail fast with a migration error telling you to use =selection= instead.
- In =new_chat_image= array mode, downloaded image filenames are normalized to array indices: =x.ext=, =x_1.ext=, =x_2.ext=, ...
- Set =pick_output_dir=true= to activate picked-folder output. You now pick the exact final folder; if =pick_output_dir= is omitted/false, native browser downloads are used as before.
- Download helper targets visible generated-image tiles and fetches their current =/backend-api/estuary/content= asset URLs directly.
- Benign upstream console noise is expected sometimes (for example =Permissions-Policy ... browsing-topics=, =connectors/check 400=, =sentinel/ping 400=, or ChatGPT's own =net::ERR_HTTP2_PING_FAILED= lines). The userscript does not treat those as failures by themselves.
- Additional upstream console warnings such as ChatGPT accessibility/router noise (=aria-hidden retained focus=, =DialogContent requires a DialogTitle=, =A router only supports one blocker at a time=) are also treated as symptoms to recover around, not as direct failure signals.
- Picked-folder mode uses the File System Access API, so unsupported browsers or blocked/canceled directory picks fail early with a clear error.
- Downloader throttling is built in: after every 10 image downloads, it waits 1.1 seconds before continuing.
- =clickDallEDownloadButtons()= may require manually scrolling to the top of the chat so the target generated images are mounted/visible.
- =waitForImageGenerationLimitReset()= is also exported for manual use on the current page; pass a nonzero =previousAssistantTurnCount= if you need to ignore older assistant messages.
- =MAGIC_RETRY= is exported so it can be used in retry arrays when customizing the image retry flow.
- =sendMessageRepeatedlyArray(...)= and =sendMessageRepeatedlyArrayChooseFile(...)= accept =options.imageRetryPrompts= (alias: =options.retryPrompts=) in =new_chat_image= mode to override the default retry queue. Entries can be raw strings / =MAGIC_RETRY= or objects like ={ prompt: "...", image_expected_p: false }=. =image_expected_p= defaults to =true=; when false, that retry step waits only until the composer is ready for the next input again, then immediately advances to the next retry step. Example: =sendMessageRepeatedlyArrayChooseFile(..., { imageRetryPrompts: [MAGIC_RETRY, { prompt: "First rewrite the prompt and put it in a markdown code block.", image_expected_p: false }, "Generate using the new safe prompt!"] })=.

** [[id:e8a38273-a5de-4a50-bbab-ada9fcdf01f8][Connecting to a running Chrome instance]]
The [[./.codex/config.toml][MCP config]] requires Chrome to be running with the remote debugging port set to 9222. It also mandates the installation of both NVM and Node v22.

*macOS*

#+begin_src :eval never
/Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome --remote-debugging-port=9222 --user-data-dir="${HOME}/tmp/chrome-profile-stable"
#+end_src

With proxy:
#+begin_src zsh :eval never
tmuxnew chrome-debug /Applications/Google\ Chrome.app/Contents/MacOS/Google\ Chrome \
--remote-debugging-port=9222 \
--user-data-dir="${HOME}/tmp/chrome-profile-stable" \
--proxy-server="socks5://127.0.0.1:1081" \
--proxy-bypass-list="localhost;127.0.0.1"
#+end_src

*Linux*

#+begin_src :eval never
/usr/bin/google-chrome --remote-debugging-port=9222 --user-data-dir=/tmp/chrome-profile-stable
#+end_src

*Windows*

#+begin_src :eval never
"C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --user-data-dir="%TEMP%\chrome-profile-stable"
#+end_src
